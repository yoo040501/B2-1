# CLI 가계부 프로그램

Python 표준 라이브러리만 사용하는 파일 기반 콘솔 가계부입니다. 거래 추가·조회·검색·수정·삭제, 월별 요약, 예산·카테고리 관리, CSV 가져오기·내보내기를 지원합니다.

거래·카테고리·예산은 JSONL 파일 3개로 나눠 영구 저장합니다. 제너레이터로 거래를 순차 처리하고, 공통 검증·데코레이터·모듈 분리로 명령별 역할을 구분했습니다. 수정·삭제와 일괄 저장에는 임시 파일을 이용한 원자적 교체를 적용합니다.

## 1. 실행 환경과 저장 위치

- Python 3.10 이상
- 외부 패키지 설치 불필요
- 저장소 최상위 폴더에서 실행

```bash
python3 -m budget_app --help
python3 -m budget_app add --help
python3 -m budget_app category add --help
```

환경에 따라 `python3`를 `python` 또는 `python3.12`로 바꿔 사용합니다. 모든 명령과 하위 명령은 `--help`를 지원합니다.

기본 저장 위치는 **현재 실행 위치 기준 `./data`**입니다. 다른 폴더를 사용하려면 공통 옵션 `--data-dir`를 명령 이름 **앞에** 지정합니다.

```bash
python3 -m budget_app --data-dir demo_data list --limit 10
```

파일은 각 저장소가 사용될 때 없으면 자동 생성되며, 기존 내용은 지우지 않습니다. 예를 들어 빈 폴더에서 `budget set`은 예산 파일을, `list`는 거래·예산 파일을 준비합니다. `add`나 `import`는 카테고리 저장소도 사용하므로 정상 실행 시 세 파일이 준비됩니다. 도움말 조회는 파일을 생성하지 않습니다.

카테고리 파일이 없으면 `food`, `transport`, `rent`, `salary`, `etc`를 기본 등록합니다. 파일이 이미 있지만 비어 있으면 기본값을 다시 채우지 않으므로 `category add`로 먼저 등록해야 합니다. 거래를 조회할 때 누락 카테고리를 자동 복구하지 않습니다.

## 2. 명령별 실행 예시

다음 예시는 Bash 또는 zsh에서 저장소 최상위 폴더를 기준으로 실행합니다. **새 임시 데이터 폴더를 사용하므로 저장소의 `data/`에 영향을 주지 않습니다.** 같은 터미널에서 순서대로 실행하면 예시 ID와 금액을 재현할 수 있습니다.

```bash
BUDGET_DEMO_DIR="$(mktemp -d)"
```

예상 출력에서는 `[LOG]`·`[TIME]`을 생략했습니다. 거래 ID는 이 예시처럼 빈 폴더에서 시작할 때 `TX-001`이며, 기존 데이터가 있는 폴더에서는 달라집니다.

### 카테고리 목록과 거래 추가

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" category list
```

```text
- food
- transport
- rent
- salary
- etc
```

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" add
```

아래 값을 대화형으로 입력합니다.

```text
날짜(YYYY-MM-DD, 엔터 시 오늘): 2026-10-28
타입(income/expense): expense
카테고리: food
금액: 15000
메모(선택): 점심
태그(쉼표 구분): 식사,친구
[저장 완료] id=TX-001
```

날짜는 `YYYY-MM-DD` 형식이며 엔터만 입력하면 실행 환경의 오늘 날짜를 사용합니다. 타입은 `income` 또는 `expense`, 카테고리는 등록된 이름, 금액은 쉼표 없는 양수 정수입니다. 메모·태그는 비워도 됩니다.

날짜·타입은 입력 직후 검사합니다. 잘못된 입력은 오류로 종료하며, 같은 실행에서 재입력을 반복해서 받지는 않습니다. `1,000`·`abc`는 정수 변환 오류, `0`·음수는 금액 검증 오류입니다.

### 거래 목록과 검색

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" list --limit 3
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" search --from 2026-10-01 --to 2026-10-31 --category food --type expense --q 점심 --tag 식사
```

두 명령 모두 다음 거래를 출력합니다.

```text
Transaction(id='TX-001', date='2026-10-28', type='expense', category='food', amount=15000, memo='점심', tags=['식사', '친구'])
```

| 항목 | 동작 |
|---|---|
| 정렬 | 거래 날짜가 최신인 순서. 같은 날짜는 파일에서 뒤에 있는 거래 우선 |
| 목록 제한 | `--limit N`, 기본 10개 |
| 검색 제한 | `--limit N`, 기본 20개 |
| 기간 | `--from`·`--to` 포함 범위. 검색은 한쪽 날짜만 지정해도 됨 |
| 카테고리·타입 | `--category`·`--type`으로 일치 여부 확인 |
| 메모 | `--q`로 대소문자를 구분하지 않는 부분 문자열 검색 |
| 태그 | `--tag`로 개별 태그와 정확히 일치하는 거래 검색 |
| 조건 조합 | 지정한 조건을 모두 만족해야 함 |

`--limit`은 1 이상입니다. 검색 결과가 제한보다 많아도 별도 생략 안내는 없으므로 더 보려면 제한을 늘립니다. 빈 목록은 `등록된 거래가 없습니다.`, 검색 결과가 없으면 `검색 결과가 없습니다.`를 출력합니다.

### 거래 수정

**수정은 옵션 방식으로 고정되어 있습니다.** 변경할 필드만 지정합니다.

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" update --id TX-001 --amount 20000
```

```text
[수정 완료] id=TX-001
```

수정 가능한 옵션은 `--date`, `--type`, `--category`, `--amount`, `--memo`, `--tags`입니다. 예를 들어 `--memo ""`와 `--tags ""`는 기존 메모와 태그를 비웁니다. 없는 ID 또는 수정 항목이 없는 요청은 오류입니다. 미등록 카테고리로 변경할 수 없습니다.

### 예산 설정과 월별 요약

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" budget set --month 2026-10 --amount 10000
```

```text
[저장 완료] 2026-10 예산 10000원
```

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" summary --month 2026-10 --top 3
```

```text
2026-10 월별 요약
총 수입: 0원
총 지출: 20000원
잔액: -20000원
예산: 10000원 (사용률 200.0%)
[경고] 월 예산을 초과했습니다!

지출 TOP 3
1. food: 20000원
```

`--top`은 1 이상이며 기본값은 3입니다. 거래가 없는 달은 `데이터 없음`과 0원 합계를 출력합니다. 예산 조회는 별도 `budget get` 명령 없이 `summary`에서 확인합니다.

예산 사용률은 `총 지출 / 예산 × 100`으로 계산하며, 수입을 차감하지 않습니다. 지출이 예산보다 **클 때** 경고를 출력합니다. 경고는 `summary` 실행 시 표시하며 별도 자동 알림은 없습니다.

같은 달의 예산을 다시 설정하면 이전 금액을 교체하고 다른 달의 예산은 유지합니다. 이전 값의 변경 이력이나 별도 감사 로그는 저장하지 않습니다.

### 카테고리 추가·삭제와 사용 중인 카테고리

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" category add
```

```text
카테고리명: books
[저장 완료] category=books
```

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" category remove
```

```text
삭제할 카테고리명: books
[삭제 완료] category=books
```

이 시점에 `food`를 삭제하려고 하면 사용 중이므로 차단합니다. 아래 오류·힌트는 stderr로 출력하며 종료 코드는 1입니다.

```text
삭제할 카테고리명: food
[오류] 잘못된 데이터: 사용 중인 카테고리는 삭제할 수 없습니다.
[힌트] 입력값을 확인하세요.
```

자동 대체 플래그는 제공하지 않습니다. 다른 카테고리로 옮기려면 새 이름을 `category add`로 등록하고, `search --category 기존이름`으로 거래를 확인한 뒤 각각 `update --id <id> --category 새이름`으로 옮깁니다. 모든 거래를 옮긴 다음 기존 카테고리를 삭제합니다. 검색 결과는 기본 20개로 제한되므로 거래가 많으면 `--limit`을 늘려 확인합니다.

### CSV 내보내기·가져오기

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" export --out "$BUDGET_DEMO_DIR/export.csv" --month 2026-10
```

출력 경로는 환경마다 달라집니다. 위 예시에서는 `[완료] <임시폴더>/export.csv (1 records)`를 출력하고 다음 파일을 만듭니다.

```csv
date,type,category,amount,memo,tags
2026-10-28,expense,food,20000,점심,"식사,친구"
```

월 대신 시작·종료일로 내보낼 수도 있습니다.

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" export --out "$BUDGET_DEMO_DIR/period.csv" --from 2026-10-01 --to 2026-10-31
```

새 데이터 폴더로 가져오면 기존 예시에 거래를 중복 추가하지 않고 결과를 확인할 수 있습니다.

```bash
BUDGET_IMPORT_DIR="$(mktemp -d)"
python3 -m budget_app --data-dir "$BUDGET_IMPORT_DIR" import --from "$BUDGET_DEMO_DIR/export.csv"
```

```text
[완료] imported=1, skipped=0
```

내보내기는 `--month` 또는 `--from`·`--to` 쌍이 필수입니다. 월과 기간을 함께 지정하면 두 조건을 모두 적용합니다. 출력 파일의 상위 폴더는 미리 있어야 하며, 기존 출력 파일은 성공 시 교체합니다. 조건에 맞는 거래가 없으면 헤더만 기록합니다. 현재 데이터 폴더의 저장 파일 3개를 출력 대상으로 지정하는 것은 차단합니다.

가져오기는 새 거래 ID를 발급합니다. 같은 CSV를 다시 가져오면 같은 내용이 중복 등록될 수 있으며, 내용 중복 검사는 하지 않습니다.

### 거래 삭제

```bash
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" delete --id TX-001
python3 -m budget_app --data-dir "$BUDGET_DEMO_DIR" list
```

```text
[삭제 완료] id=TX-001
등록된 거래가 없습니다.
```

없는 ID를 삭제하면 실패 메시지와 힌트를 출력하고 종료 코드 1을 반환합니다.

### 프로그램 재실행 후 저장 확인

다음은 입력을 자동으로 전달하는 재현용 예시입니다. `add`가 종료된 뒤 **별도 Python 프로세스의 `list`**로 같은 폴더를 조회합니다.

```bash
BUDGET_PERSIST_DIR="$(mktemp -d)"
python3 -m budget_app --data-dir "$BUDGET_PERSIST_DIR" add <<'INPUT'
2026-10-28
expense
food
5000
재실행 확인
확인
INPUT
python3 -m budget_app --data-dir "$BUDGET_PERSIST_DIR" list
```
두 번째 프로세스의 예상 출력입니다.

```text
Transaction(id='TX-001', date='2026-10-28', type='expense', category='food', amount=5000, memo='재실행 확인', tags=['확인'])
```

## 3. 저장 파일과 CSV 스키마

### 내부 저장: JSONL

한 줄에 JSON 객체 하나를 기록하며 UTF-8을 사용합니다.

| 파일 | 저장 항목 |
|---|---|
| `transactions.jsonl` | `id`, `date`, `type`, `category`, `amount`, `memo`, `tags` |
| `categories.jsonl` | `name` |
| `budgets.jsonl` | `month`, `amount` |

거래 저장 예시입니다.

```json
{"id": "TX-001", "date": "2026-10-28", "type": "expense", "category": "food", "amount": 15000, "memo": "점심", "tags": ["식사", "친구"]}
```

메모의 기본값은 빈 문자열, 태그의 기본값은 빈 목록입니다. ID는 현재 저장된 최대 번호 다음 값으로 생성하며 최소 3자리로 표시합니다. 삭제된 최대 ID는 다시 사용될 수 있으므로 전체 사용 이력에 걸친 영구 고유 번호는 아닙니다.

### 교환 형식: CSV

**UTF-8, BOM 없음, 헤더 포함**을 사용합니다. 현재 읽기는 `utf-8`이므로 BOM이 있는 파일은 BOM 없는 UTF-8로 변환해야 합니다.

| 열 | 필수 | 형식 |
|---|---|---|
| `date` | 예 | 실제 존재하는 날짜, `YYYY-MM-DD` |
| `type` | 예 | `income` 또는 `expense` |
| `category` | 예 | 등록된 카테고리 이름 |
| `amount` | 예 | 쉼표 없는 양수 정수 |
| `memo` | 아니오 | 문자열. 생략 시 빈 문자열 |
| `tags` | 아니오 | 쉼표로 구분한 태그. 생략 시 빈 목록 |

내보내기 열 순서는 아래와 같습니다. 가져오기는 헤더 이름으로 읽으므로 순서를 바꿔도 되지만 이름은 정확해야 합니다. 중복 헤더와 필수 헤더 누락은 파일 전체의 오류로 처리합니다. `id`는 교환 스키마에 포함하지 않습니다.

```csv
date,type,category,amount,memo,tags
2026-10-28,expense,food,15000,점심,"식사,친구"
2026-10-28,income,salary,100000,용돈,
```

쉼표·따옴표·줄바꿈이 포함된 필드는 CSV 규칙에 따라 따옴표로 감싸며, 필드 내부의 큰따옴표는 두 번 씁니다. 태그 앞뒤 공백과 빈 태그는 제거합니다. 태그 이름 자체에 쉼표를 넣는 방식은 지원하지 않습니다.

다음 두 행은 다르게 처리됩니다.

```csv
2026-10-28,expense,food,1000,정상 행,"meal,friend"
2026-10-28,expense,food,2000,열 초과 행,meal,friend
```

첫 행의 태그는 두 개로 저장됩니다. 두 번째 행은 헤더보다 값이 많으므로 해당 행을 건너뜁니다.

### JSONL 선택 이유와 트레이드오프

| 비교 | JSONL | CSV |
|---|---|---|
| 자료형 | 숫자·문자열·목록 보존 | 읽은 문자열을 숫자·목록으로 변환해야 함 |
| 태그 예시 | `"tags": ["식사", "친구"]` | `"식사,친구"`를 CSV 필드 하나로 인용 |
| 스트리밍 | 한 줄씩 처리 | CSV 레코드씩 처리. 인용된 필드는 여러 줄일 수 있음 |
| 활용 | 내부 데이터 구조 보존에 적합 | 스프레드시트 등 외부 프로그램과 교환하기 편리 |
| 특정 거래 수정·삭제 | 파일 전체 재작성 필요 | 파일 전체 재작성 필요 |

태그 목록과 금액의 자료형을 보존하기 위해 내부 저장은 JSONL을 선택했습니다. 필드 이름을 각 행에 반복하므로 저장 크기가 늘 수 있지만, 실제 파일 크기는 데이터에 따라 달라집니다. 포맷별 크기·속도 비교 수치를 실측한 것은 아닙니다.

## 4. 데이터 보존과 가져오기 리포트

### 추가 저장과 원자적 교체

`append_jsonl()`은 거래·카테고리 한 건을 파일 끝에 추가합니다. 기존 파일의 마지막에 줄바꿈이 없으면 먼저 줄바꿈을 넣어 JSON 객체가 같은 줄에 붙지 않도록 합니다.

`atomic_write()`는 원본과 같은 폴더에 임시 파일을 만들고, 쓰기가 끝나면 `flush()`·`os.fsync()` 후 `os.replace()`로 최종 파일을 교체합니다. 교체 전 예외가 발생하면 원본을 유지하고 임시 파일을 정리합니다.

| 작업 | 저장 방식 |
|---|---|
| 거래·카테고리 한 건 추가 | `append_jsonl()`로 추가 쓰기 |
| 거래 수정·삭제·일괄 저장 | 임시 파일 작성 후 원자적 교체 |
| 예산 설정·카테고리 삭제 | 임시 파일 작성 후 원자적 교체 |
| CSV 내보내기 | 임시 파일 작성 후 원자적 교체 |

모든 쓰기가 원자적 교체를 사용하는 것은 아닙니다. 또한 파일 하나의 교체와 여러 파일을 함께 변경하는 트랜잭션은 다릅니다. 명령 시작 시 생성한 저장 파일까지 오류 발생 시 되돌리지는 않습니다.

### CSV 가져오기 정책

| 상황 | 처리 |
|---|---|
| 정상 행 | 새 ID를 발급해 가져오기 대상에 포함 |
| 날짜·타입·금액 오류, 미등록 카테고리, 헤더보다 많은 값 | 경고를 출력하고 해당 행을 건너뛰며 `skipped` 증가 |
| 필수 헤더 누락·중복 헤더 | 가져오기 실패 |
| CSV 구문 오류, 파일 읽기·쓰기 오류 | 가져오기 취소. 이미 읽은 정상 행도 거래 파일에 반영하지 않음 |
| 정상 거래가 한 건 이상이고 끝까지 읽기 성공 | 기존 거래와 새 거래를 한 번의 파일 교체로 반영 |
| 정상 거래가 한 건도 없음 | 거래 파일을 재작성하지 않고 `imported=0`으로 완료 |

`save_many_atomic()`은 제너레이터에서 첫 정상 거래 하나를 먼저 확인합니다. 거래가 있으면 `chain((first,), iterator)`로 첫 거래와 나머지를 순차 저장합니다. CSV 전체를 리스트로 만들지 않으며, 뒤쪽에서 오류가 발생해도 기존 거래 파일을 보존합니다.

### 건너뛴 행 확인과 리포트 저장

다음 예시는 앞의 명령 예시에서 만든 `BUDGET_DEMO_DIR`를 사용합니다. 새 데이터 폴더에 정상 한 건과 금액 오류 한 건을 가져옵니다.

```bash
cat > "$BUDGET_DEMO_DIR/mixed.csv" <<'CSV'
date,type,category,amount,memo,tags
2026-10-28,expense,food,1000,정상 행,"meal,friend"
2026-10-28,expense,food,abc,잘못된 금액,
CSV

BUDGET_REPORT_DIR="$(mktemp -d)"
python3 -m budget_app --data-dir "$BUDGET_REPORT_DIR" import --from "$BUDGET_DEMO_DIR/mixed.csv" > "$BUDGET_DEMO_DIR/import-result.txt" 2> "$BUDGET_DEMO_DIR/import-stderr.log"
cat "$BUDGET_DEMO_DIR/import-result.txt"
cat "$BUDGET_DEMO_DIR/import-stderr.log"
```

정상 결과 파일에는 다음 내용이 저장됩니다.

```text
[완료] imported=1, skipped=1
```

stderr 파일에는 다음 경고가 저장됩니다.

```text
[건너뜀] 레코드 3: 금액은 쉼표 없는 정수로 입력하세요. 예: 1000
```

현재 출력 문구의 `레코드 N`에서 N은 `reader.line_num`, 즉 **헤더를 포함한 CSV의 현재 물리적 줄 번호**입니다. 메모에 인용된 줄바꿈이 있으면 해당 레코드의 마지막 줄 번호를 가리킵니다.

별도 리포트 파일을 자동 생성하지는 않으며 위처럼 셸 리다이렉션으로 보관할 수 있습니다. 경고가 나온 뒤 파일 전체 오류로 취소될 수도 있으므로 최종 완료 메시지와 종료 코드를 함께 확인합니다.

### 동시 실행과 파일 잠금

현재 파일 잠금은 구현하지 않았습니다. **같은 데이터 폴더를 변경하는 명령은 한 번에 하나씩 실행**하는 것을 전제로 합니다. 두 프로세스가 동시에 저장하면 ID 발급 충돌이나 변경 유실이 생길 수 있으며, 원자적 교체만으로 이를 막을 수는 없습니다.

동시 쓰기가 필요해지면 ID 조회부터 최종 저장까지의 읽기·수정·쓰기 구간에 프로세스 간 잠금을 적용해야 합니다. 여러 저장소를 함께 잠글 때는 항상 같은 순서로 획득하도록 설계해야 합니다. 이 내용은 확장 방향이며 현재 구현된 기능은 아닙니다.

## 5. 오류 출력과 종료 코드

출력 규칙은 다음과 같습니다.

| 출력 채널 | 내용 |
|---|---|
| stdout | 거래·카테고리 목록, 요약, 저장·수정·삭제·가져오기 완료 결과 |
| stderr | 오류·해결 힌트, 가져오기 행별 경고, `[LOG]`·`[TIME]` |

검증 함수와 저장소는 처리할 오류를 예외로 전달합니다. 일반 명령은 `main()`에 적용한 `handle_errors`가 원인·힌트를 안내하고, CSV 가져오기는 handler에서 CSV 관련 오류를 별도로 안내합니다. 같은 오류를 각 계층에서 중복 출력하지 않는 방식입니다. 저장소를 직접 호출하면 이 CLI 오류 변환이 적용되지 않습니다.

대화형 금액 입력 오류 예시입니다.

```text
[오류] 잘못된 데이터: 금액은 쉼표 없는 정수로 입력하세요. 예: 1000
[힌트] 입력값을 확인하세요.
```

update·budget의 금액 옵션은 `amount_argument()`가 `parse_amount()`의 오류를 `argparse.ArgumentTypeError`로 변환합니다. 따라서 옵션 오류는 argparse의 사용법과 함께 안내됩니다.

```text
budget_app update: error: argument --amount: 금액은 쉼표 없는 정수로 입력하세요. 예: 1000
```

| 종료 코드 | 의미와 예시 |
|---|---|
| `0` | 정상 완료. 도움말, 조회 결과 없음, 검증 실패 행을 건너뛰고 끝난 import도 포함 |
| `1` | handler에서 처리한 입력·파일 오류. 잘못된 대화형 금액, 없는 ID, 사용 중 카테고리 삭제, CSV 파일 오류 등 |
| `2` | argparse 인자 오류. 필수 옵션 누락, 잘못된 옵션 값, update·budget의 0·음수·문자 금액 등 |
| `130` | 사용자 입력 중단 또는 EOF |

셸에서는 명령 직후 `echo $?`로 종료 코드를 확인할 수 있습니다. stderr에 경고·로그가 있다고 해서 실패한 것은 아닙니다. `imported=0, skipped=N`으로 끝난 가져오기도 현재 정책상 종료 코드 0입니다.

JSON 문법 오류, 거래 생성 시 필드 누락·불필요한 필드, 카테고리의 `name` 누락, 예산 조회 시 필수 항목·금액 오류 등은 처리합니다. 저장된 모든 필드의 자료형·값을 완전히 검증하는 것은 아니므로 수동 편집으로 손상된 모든 파일의 처리를 보장하지는 않습니다.

### 공통 함수와 타입 힌트

| 함수 | 반환 계약과 용도 |
|---|---|
| `parse_amount(value: str \| None) -> int` | 문자열 금액을 정수로 변환하고 양수인지 검사합니다. add·CSV와 금액 옵션에서 재사용합니다. |
| `validate_amount(value: int) -> None` | 이미 정수인 금액을 검증합니다. update·budget handler에서도 사용합니다. |
| `parse_tags(text: str) -> list[str]` | 쉼표 분리, 공백 제거, 빈 태그 제외를 add·update·import에서 공유합니다. |
| `validate_category(...) -> None` | 등록된 카테고리인지 공통 검사합니다. |
| `search_transactions(...) -> Iterator[Transaction]` | 조건에 맞는 거래를 순차 전달합니다. |
| `latest_transactions(...) -> list[Transaction]` | 입력 iterable에서 최신순으로 최대 `limit`개를 선택합니다. |
| `summarize_month(...) -> tuple[int, int, dict[str, int], int]` | 수입·지출·카테고리별 지출·거래 수를 반환합니다. |

타입 힌트는 호출·반환 계약을 설명하며 실행 중 검증을 대신하지 않습니다. 파일 읽기는 `read_jsonl()`·`TransactionRepository.load()`의 제너레이터로 이어지고, 서비스는 `Iterator[Transaction]`·`Iterable[Transaction]`으로 순차 처리 대상을 표현합니다.

### 실제 적용한 데코레이터

| 데코레이터 | 적용 함수 | 역할 |
|---|---|---|
| `handle_errors` | `cli.main()` | 처리 대상 예외를 원인·힌트와 실패 종료 코드로 변환 |
| `log_action` | `TransactionRepository.save/update/delete()` | 실행 시작을 stderr에 `[LOG]`로 출력. 성공 확인 로그는 아님 |
| `time_action` | `handle_search()`, `handle_summary()` | 성공·실패에 관계없이 해당 handler의 경과 시간을 stderr에 출력 |

시간 출력 예시는 `[TIME] handle_summary: 0.0004s`입니다. 실제 값은 실행마다 달라지며 해당 handler의 실행 범위를 측정합니다.

## 7. 스트리밍과 대용량 처리

### 메모리 사용을 줄이는 방식

거래 100,000건 중 최신 10건을 보여주는 상황을 가정합니다.

| 방식 | 거래를 보관하는 규모 |
|---|---|
| 전체 거래를 `list(repo.load())`로 만든 뒤 정렬 | 전체 100,000건에 비례 |
| 현재 구현: 제너레이터를 `heapq.nlargest(10, ...)`에 전달 | 최대 10건에 비례하는 선택 결과와 현재 처리 중인 거래 |

이는 **구조에 따른 비교이며 메모리 사용량을 MB 단위로 실측한 결과는 아닙니다.** 최신순을 결정하려면 파일 전체는 확인하지만 전체 거래를 먼저 리스트로 만들지 않습니다. 검색도 필터 제너레이터의 결과를 같은 정렬 함수에 전달합니다.

월별 요약은 거래 목록 대신 수입·지출 합계와 카테고리별 지출 합계를 유지합니다. CSV 가져오기도 전체 행을 모으지 않고 등록 카테고리 집합과 현재 행·첫 정상 거래 등을 보관합니다.

### 시간복잡도와 파일 재작성 비용

기존 거래 수를 `N`, CSV 입력 행 수를 `M`, 출력 제한을 `K`, 검색 일치 건수를 `R`, 지출 카테고리 수를 `C`, 예산 수를 `B`로 둡니다. 레코드 길이는 일정하다고 가정합니다.

| 기능 | 현재 구현 | 주요 시간복잡도 |
|---|---|---|
| 목록 | 전체 순회 후 최신 K개 선택 | `O(N log(K+1))` |
| 검색 | 조건 필터링 후 최신 K개 선택 | `O(N + R log(K+1))` |
| 요약 | 거래 합산·카테고리 정렬·예산 조회 | `O(N + C log(C+1) + B)` |
| 거래 추가 | 최대 ID 조회·중복 ID 검사·추가 쓰기 | `O(N)` |
| 거래 수정·삭제 | ID 존재 확인 후 파일 재작성 | `O(N)` |
| CSV 가져오기 | 최대 ID 조회·정상 행 검사·필요 시 기존 거래 복사 | `O(N + M)` |
| CSV 내보내기 | 전체 순회·조건 필터링·CSV 기록 | `O(N)` |

기존 거래 100,000건과 CSV 1,000행을 처리하면 ID 조회에서 기존 거래를 한 번 읽고, 정상 거래가 있으면 임시 파일 작성에서 다시 복사합니다. CSV 행마다 기존 거래 100,000건을 다시 읽는 구조는 아닙니다. 정상 거래가 0건이면 ID 조회·CSV 검사는 수행하지만 거래 파일 재작성은 생략합니다.

수정·삭제와 일괄 저장은 임시 파일을 쓰므로 기존 데이터 크기에 비례하는 추가 디스크 공간이 필요합니다.

### 향후 개선 우선순위

다음은 미구현 확장 방향입니다. 비용은 상대적인 구현·검증 난이도이며 실측 일정은 아닙니다.

| 필요 상황 | 개선 방향 | 조건부 우선순위 | 예상 비용·주의점 |
|---|---|---|---|
| 여러 프로세스가 동시에 수정 | ID 발급과 저장 구간에 파일 잠금 적용 | 동시 쓰기 도입 전 높음 | 중간. 잠금 범위·획득 순서·플랫폼 차이 검토 |
| 실수로 삭제한 데이터 복구 필요 | 타임스탬프 백업·복구 절차 추가 | 운영 데이터 사용 시 높음 | 낮음~중간. 보관 용량·복구 절차 필요 |
| 거래 수 증가로 조회가 느려짐 | 월별 분할 또는 별도 인덱스·합계 캐시 | 성능 측정 후 중간 | 중간~높음. 수정·삭제와 일관성 유지 필요 |
| 더 큰 규모·동시성 요구 | SQLite 등 데이터베이스로 전환 | 과제 이후 확장 | 높음. 현재 JSONL/CSV 저장 조건을 벗어나는 설계 변경 |

## 8. 테스트와 알려진 제한

프로젝트 최상위 폴더에서 실행합니다.

```bash
python3 -B -m unittest discover -s tests -v
```

현재 기존 테스트 메서드는 40개이며, Python 3.12.14에서 모두 통과했습니다. 일부는 여러 입력을 `subTest`로 확인합니다. 테스트와 위 문서의 재실행 예시는 임시 데이터 폴더를 사용하므로 저장소의 기본 `data/`를 대상으로 실행하지 않습니다.

| 테스트 파일 | 주요 검증 |
|---|---|
| `test_repository.py` | 저장·재조회, 수정·삭제 시 다른 거래 보존, 중복·없는 ID, ID 생성, 일괄 저장 롤백 |
| `test_stores.py` | 카테고리 중복·삭제·빈 이름, 예산 유지·변경·미설정 |
| `test_validators.py` | 날짜·윤년·월·기간·타입·금액 검증 |
| `test_csv_io.py` | CSV 왕복 변환, 기간 필터, 저장 파일 덮어쓰기 차단, 내보내기 실패 시 기존 파일 보존 |
| `test_cli.py` | 명령별 도움말, 별도 프로세스 간 CRUD, 종료 코드, 예산 조회, 잘못된 CSV 안내·거래 보존 |

현재 제한은 다음과 같습니다.

- 파일 잠금·자동 백업·반복 거래 생성·CSV 내용 중복 검사는 구현하지 않았습니다.
- 거래 ID는 삭제 후 다시 사용될 수 있습니다.
- BOM이 있는 CSV는 지원하지 않습니다.
- CSV 필드 길이는 표준 `csv` 모듈의 기본 제한을 사용합니다. 검증 환경에서는 131,072자보다 긴 메모를 저장·내보낼 수 있어도 다시 가져오면 실패합니다.
- 저장 파일을 직접 편집했을 때 발생할 수 있는 모든 자료형·값 손상을 처리하지는 않습니다.

테스트 통과는 현재 검증 범위에 대한 결과이며 동시 실행이나 모든 파일 손상 상황까지 보장하지 않습니다.
