# CLI 가계부 프로그램

Python 표준 라이브러리로 만든 파일 기반 콘솔 가계부입니다. 거래 추가·조회·검색·수정·삭제, 월별 요약, 예산·카테고리 관리와 CSV 가져오기·내보내기를 지원합니다.

내부 데이터는 JSONL 파일 3개에 저장합니다. 파일 읽기는 제너레이터로 처리하고, 수정·삭제와 CSV 일괄 저장에는 임시 파일을 이용한 원자적 교체를 적용합니다.

## 1. 실행 방법

- Python 3.10 이상
- 외부 패키지 설치 불필요
- 프로젝트 최상위 폴더에서 실행

```bash
python3 -m budget_app --help
python3 -m budget_app add --help
python3 -m budget_app category add --help
```

환경에 따라 Python 실행 명령이 `python`이면 예시의 `python3`를 바꿔 사용합니다. 모든 명령과 하위 명령은 `--help`를 지원합니다.

기본 저장 위치는 **실행 위치를 기준으로 한 `./data`**입니다. 저장 폴더를 바꾸려면 공통 옵션 `--data-dir`를 명령 이름 앞에 지정합니다.

```bash
python3 -m budget_app --data-dir demo_data list
```

일반 명령을 처음 실행하면 저장 폴더와 파일 3개가 생성됩니다. 도움말만 조회할 때는 초기화하지 않습니다. 기존 파일의 내용은 초기화로 지워지지 않습니다.

## 2. 주요 명령

### 거래 추가

```bash
python3 -m budget_app add
```

날짜, 타입, 카테고리, 금액, 메모, 태그를 순서대로 입력합니다.

- 날짜: `YYYY-MM-DD`. 엔터만 입력하면 오늘 날짜
- 타입: `income` 또는 `expense`
- 카테고리: 등록된 이름
- 금액: 0보다 큰 정수
- 메모·태그: 선택 항목. 태그는 쉼표로 구분

처음 생성한 빈 데이터 폴더에서의 입력·출력 예시입니다. `[LOG]` 등 부가 출력은 생략했습니다.

```text
날짜(YYYY-MM-DD, 엔터 시 오늘): 2026-10-28
타입(income/expense): expense
카테고리: food
금액: 15000
메모(선택): 점심
태그(쉼표 구분): 식사,친구
[저장 완료] id=TX-001
```

잘못된 입력은 오류로 종료합니다. 같은 실행 안에서 재입력을 반복해서 받는 방식은 아닙니다.

### 목록과 검색

```bash
python3 -m budget_app list --limit 10
python3 -m budget_app search --from 2026-10-01 --to 2026-10-31
python3 -m budget_app search --category food --type expense
python3 -m budget_app search --q 점심 --tag 식사 --limit 50
```

| 항목 | 동작 |
|---|---|
| 정렬 | 거래 날짜가 최신인 순서. 같은 날짜는 파일에서 뒤에 있는 거래 우선 |
| 목록 기본 제한 | 10개 |
| 검색 기본 제한 | 20개. 더 보려면 `--limit`을 늘림 |
| 기간 | 시작일·종료일 포함. 검색은 한쪽 날짜만 지정해도 됨 |
| 메모 `--q` | 대소문자를 구분하지 않는 부분 문자열 검색 |
| 태그 `--tag` | 개별 태그와 정확히 일치하는 거래 검색 |
| 조건 조합 | 지정한 조건을 모두 만족해야 함 |

목록과 검색은 현재 `Transaction(...)` 형식으로 출력합니다. 검색 결과가 제한보다 많아도 별도의 생략 안내는 없으므로 기본 20개 제한에 주의합니다. 목록이 비어 있으면 거래 출력이 없고, 검색 결과가 없으면 안내 문구를 출력합니다.

### 수정과 삭제

**수정은 옵션 방식으로 고정되어 있습니다.** 변경할 필드만 지정합니다.

```bash
python3 -m budget_app update --id TX-001 --amount 20000
python3 -m budget_app update --id TX-001 --date 2026-10-27 --type expense --category food
python3 -m budget_app update --id TX-001 --memo "저녁 식사" --tags "식사,친구"
python3 -m budget_app delete --id TX-001
```

수정 가능한 옵션은 `--date`, `--type`, `--category`, `--amount`, `--memo`, `--tags`입니다. 없는 ID 또는 수정 항목이 없는 요청은 오류로 처리합니다. 예시 ID는 실제 저장된 ID로 바꿔 사용합니다.

### 카테고리

```bash
python3 -m budget_app category list
python3 -m budget_app category add
python3 -m budget_app category remove
```

추가·삭제는 카테고리 이름을 대화형으로 입력합니다. 빈 이름과 중복 이름은 추가할 수 없으며, 거래에서 사용 중인 카테고리는 삭제할 수 없습니다.

카테고리 파일이 없으면 `food`, `transport`, `rent`, `salary`, `etc`를 생성합니다. 파일이 이미 있지만 비어 있으면 기본값을 다시 채우지는 않습니다. 사용할 카테고리를 `category add`로 먼저 등록해야 합니다.

현재는 명령 실행 전에 거래를 검사하여, 거래에서 사용하지만 카테고리 목록에 없는 이름을 자동 복구합니다. 따라서 조회 명령도 카테고리 파일을 변경할 수 있습니다.

### 예산과 월별 요약

```bash
python3 -m budget_app budget set --month 2026-10 --amount 10000
python3 -m budget_app summary --month 2026-10 --top 3
```

월별 예산은 양수 정수이며, 같은 달에 다시 설정하면 교체됩니다. 예산 조회는 `summary`에서 확인합니다. `--top`의 기본값은 3입니다.

해당 월에 지출 15,000원 한 건과 예산 10,000원이 있는 경우의 출력 예시입니다. 실행 시간은 환경에 따라 달라집니다.

```text
2026-10 월별 요약
총 수입: 0원
총 지출: 15000원
잔액: -15000원
예산: 10000원 (사용률 150.0%)
[경고] 월 예산을 초과했습니다!

지출 TOP 3
1. food: 15000원
```

거래가 없는 달은 `데이터 없음`과 0원 합계를 출력합니다. 설정된 예산이 있으면 함께 표시합니다.

### CSV 내보내기와 가져오기

```bash
python3 -m budget_app export --out export.csv --month 2026-10
python3 -m budget_app export --out period.csv --from 2026-10-01 --to 2026-10-15
python3 -m budget_app import --from import.csv
```

- 내보내기는 `--month` 또는 `--from`·`--to` 쌍이 필요합니다.
- 월과 기간을 함께 지정하면 두 조건을 모두 적용합니다. 기간을 지정할 때는 시작·종료일이 모두 필요합니다.
- 내보내기 파일의 상위 폴더는 미리 있어야 합니다.
- 출력 대상이 현재 데이터 폴더의 저장 파일 3개 중 하나이면 차단합니다.
- 기존 출력 파일은 성공 시 교체됩니다. 조건에 맞는 거래가 없으면 헤더만 기록합니다.
- 가져오기는 새 거래 ID를 발급합니다. 같은 CSV를 다시 가져오면 같은 내용의 거래가 중복 등록될 수 있습니다.

완료 시 내보내기는 파일 경로와 건수, 가져오기는 `imported`와 `skipped` 건수를 출력합니다.

## 3. 저장 파일과 CSV 스키마

### 내부 저장: JSONL

한 줄에 JSON 객체 하나를 기록하며 UTF-8을 사용합니다.

| 파일 | 저장 항목 |
|---|---|
| `transactions.jsonl` | `id`, `date`, `type`, `category`, `amount`, `memo`, `tags` |
| `categories.jsonl` | `name` |
| `budgets.jsonl` | `month`, `amount` |

거래는 `Transaction` dataclass로 표현합니다. 메모의 기본값은 빈 문자열, 태그의 기본값은 빈 목록입니다. 날짜·타입·금액은 CLI와 CSV 가져오기에서 공통 검증 함수를 사용합니다.

ID는 현재 저장된 최대 번호 다음 값으로 생성하며 `TX-001`처럼 최소 3자리로 표시합니다. 삭제된 최대 ID는 나중에 재사용될 수 있으므로, 전체 사용 이력에 걸친 영구 고유 번호는 아닙니다.

### 교환 형식: CSV

**UTF-8, BOM 없음, 헤더 포함**으로 저장합니다. 현재 읽기는 `utf-8`을 사용하므로 BOM이 있는 파일은 BOM 없는 UTF-8로 변환해야 합니다.

| 열 | 필수 | 형식 |
|---|---|---|
| `date` | 예 | 실제 존재하는 날짜, `YYYY-MM-DD` |
| `type` | 예 | `income` 또는 `expense` |
| `category` | 예 | 등록된 카테고리 이름 |
| `amount` | 예 | 0보다 큰 정수 |
| `memo` | 아니오 | 문자열. 생략 시 빈 문자열 |
| `tags` | 아니오 | 쉼표로 구분한 태그. 생략 시 빈 목록 |

내보내기 열 순서는 아래와 같습니다. 가져오기는 헤더 이름으로 열을 찾으므로 순서를 바꿔도 되지만, 이름은 정확히 일치해야 합니다. `id`는 교환 스키마에 포함하지 않습니다.

```csv
date,type,category,amount,memo,tags
2026-10-28,expense,food,15000,점심,"식사,친구"
2026-10-28,income,salary,100000,용돈,
```

쉼표·따옴표·줄바꿈이 포함된 필드는 CSV 규칙에 맞게 따옴표로 감쌉니다. 필드 안의 큰따옴표는 두 번 씁니다. 내보내기에서는 표준 `csv` 모듈이 이를 처리합니다. 태그 앞뒤 공백과 빈 태그는 제거하며, 태그 이름 자체에 쉼표를 포함하는 방식은 지원하지 않습니다.

### JSONL을 선택한 이유

| 비교 | JSONL | CSV |
|---|---|---|
| 자료형 | 숫자·문자열·목록을 그대로 표현 | 읽은 값을 숫자·목록으로 변환해야 함 |
| 스트리밍 | 한 줄씩 읽기 가능 | CSV 레코드 단위로 읽기 가능 |
| 태그 표현 | 문자열 목록으로 저장 | 쉼표 구분 문자열과 CSV 따옴표 처리가 필요 |
| 활용 | 내부 데이터 구조 보존에 적합 | 스프레드시트 등 외부 프로그램과 교환하기 편리 |
| 공통 한계 | 특정 거래 수정·삭제 시 파일 재작성 필요 | 특정 거래 수정·삭제 시 파일 재작성 필요 |

태그 목록과 금액의 자료형을 보존하기 위해 내부 저장은 JSONL을 선택했습니다. CSV는 외부 교환용으로만 사용합니다.

## 4. 데이터 보존과 오류 처리

### 원자적 교체

`atomic_write()`는 원본과 같은 폴더에 임시 파일을 만들고, 쓰기가 끝나면 `flush()`·`os.fsync()` 후 `os.replace()`로 최종 파일을 교체합니다. 처리 중 예외가 나면 교체하지 않고 임시 파일을 정리합니다.

적용 대상은 거래 수정·삭제·일괄 저장, 예산 설정, 카테고리 삭제, CSV 내보내기입니다. 단일 거래와 카테고리 추가는 파일 끝에 직접 덧붙이는 방식입니다. 모든 쓰기가 원자적 교체를 사용하는 것은 아닙니다.

### CSV 가져오기 정책

| 상황 | 처리 |
|---|---|
| 정상 행 | 가져오기 대상에 포함 |
| 날짜·타입·금액 오류, 미등록 카테고리 등 행 검증 실패 | 해당 행을 건너뛰고 `skipped` 증가 |
| 필수 헤더 누락 | 가져오기 실패 |
| 닫히지 않은 따옴표 등 CSV 구문 오류, 파일 읽기·쓰기 오류 | 가져오기 취소, 기존 거래 파일 보존 |
| 정상적으로 끝까지 읽음 | 기존 거래와 정상 행을 한 번의 파일 교체로 반영 |

검증에 실패한 행 하나 때문에 전체를 취소하는 정책은 아닙니다. 정상 행은 모으지 않고 제너레이터로 임시 파일에 전달하며, 중간 예외가 발생하면 이미 전달한 정상 행도 최종 거래 파일에 반영하지 않습니다.

이 보존 범위는 거래 파일입니다. 명령 시작 시 이루어지는 저장 파일 생성과 카테고리 자동 복구까지 함께 되돌리는 다중 파일 트랜잭션은 아닙니다.

### 오류 안내와 종료 코드

일반 입력 오류는 `ValueError`로 전달하고 `handle_errors`에서 오류·힌트를 표준 오류 출력(`stderr`)으로 안내합니다. CSV 가져오기는 파일에 맞는 안내를 별도로 출력합니다.

```text
[오류] 잘못된 데이터: 타입은 income 또는 expense여야 합니다.
[힌트] 입력값을 확인하세요.
```

| 종료 코드 | 의미 |
|---|---|
| `0` | 정상 완료. 검증 실패 행을 건너뛰고 완료한 import도 포함 |
| `1` | 처리한 입력·파일 오류 |
| `2` | argparse의 인자 오류. 예: 필수 옵션 누락, 정수 옵션에 문자 입력 |
| `130` | 사용자 입력 중단 또는 EOF |

argparse 오류는 자체 사용법·오류 형식으로 출력합니다. `[LOG]`와 `[TIME]`도 stderr로 출력하므로 stderr에 내용이 있다는 것만으로 실패를 판단하지 말고 종료 코드를 확인해야 합니다.

JSON 문법 오류, 거래 객체 생성 시 필드 누락·불필요한 필드, 카테고리 조회 시 `name` 누락, 예산 조회 시 필수 항목 누락·조회 대상 금액 오류를 안내하도록 처리했습니다. 저장된 모든 필드의 자료형과 값을 완전히 검증하는 것은 아니므로, 수동으로 변경한 파일의 모든 손상을 처리한다고 보장하지는 않습니다.

### 현재 제한

- 동시에 여러 프로세스가 같은 데이터를 변경할 때의 파일 잠금은 구현하지 않았습니다.
- 카테고리 자동 복구가 거래 전체를 읽으므로, 거래 파일 오류가 다른 명령 실행에도 영향을 줄 수 있습니다.
- 가져오기 중복 내용 검사, 백업 명령, 반복 거래 생성은 구현하지 않았습니다.

## 5. 코드 구조와 학습 요소

| 파일 | 책임 |
|---|---|
| `__main__.py` | 실행 진입점과 종료 코드 전달 |
| `cli.py` | 인자 해석 후 저장소 초기화, 카테고리 복구, 명령 분기 |
| `parser.py` | argparse 명령·옵션 정의 |
| `commands/` | 사용자 입력·출력과 명령별 처리 |
| `models.py` | `Transaction` dataclass |
| `repository.py` | JSONL 읽기·쓰기, 거래·예산·카테고리 저장소 |
| `service.py` | 검색, 월별 합산, 카테고리 복구 |
| `csv_io.py` | CSV 가져오기·내보내기 |
| `validators.py` | 날짜·기간·월·타입·금액 검증 |
| `decorators.py` | 예외 처리·로그·시간 측정 |
| `tests/` | 표준 unittest 기반 테스트 |

저장소는 `TransactionRepository`의 `save/load/update/delete/next_id/save_many_atomic`, `CategoryStore`의 `load/add/remove`, `BudgetStore`의 `set/get`으로 역할을 나눴습니다.

- **제너레이터:** `read_jsonl()`, `load()`, `search_transactions()`가 데이터를 순차 전달합니다. 최신순 목록·검색은 `heapq.nlargest()`로 제한된 개수만 보관합니다. 파일 전체를 확인하지만 전체 거래를 먼저 리스트로 만들지는 않습니다.
- **타입 힌트:** 모델 필드와 함수 입출력에 적용했습니다. 예를 들어 `import_transactions()`의 반환값은 `tuple[int, int]`이며 각각 가져온 건수와 건너뛴 건수입니다. 타입 힌트 자체가 실행 중 검증을 대신하지는 않습니다.
- **공통 쓰기 함수:** `write_jsonl()`을 단일·일괄 저장에서 재사용합니다.

### 실제 적용한 데코레이터

| 데코레이터 | 적용 위치 | 역할 |
|---|---|---|
| `handle_errors` | `main()` | 처리 대상 예외를 오류·힌트와 실패 종료 코드로 변환 |
| `log_action` | 거래 저장·수정·삭제 | 실행 시작을 `[LOG]`로 출력. 성공 확인 로그는 아님 |
| `time_action` | 검색·월별 요약 명령 | `perf_counter()`로 경과 시간을 측정해 `[TIME]` 출력 |

시간 출력 형태는 `[TIME] handle_summary: 0.0004s`입니다. 수치는 예시이며 실행 환경마다 달라집니다. 측정 범위는 해당 명령 함수이므로, 그 전에 수행하는 CLI 초기화·카테고리 복구 시간은 포함하지 않습니다.

## 6. 대용량 데이터 병목 분석

아래 내용은 **코드 구조에 따른 분석이며, 10만 건 실측 벤치마크 결과가 아닙니다.**

기존 거래 수를 `N`, 가져올 CSV 행 수를 `M`, 출력 제한을 `K`, 검색 일치 건수를 `R`, 지출 카테고리 수를 `C`, 예산 레코드 수를 `B`로 둡니다. 레코드 길이를 일정하다고 가정합니다. 표는 주된 명령 처리 비용이며 공통 카테고리 복구 비용은 별도로 봅니다.

| 기능 | 현재 구현 | 주요 시간복잡도 |
|---|---|---|
| 목록 | 전체 순회 후 상위 K개 선택 | `O(N log(K+1))` |
| 검색 | 전체 필터링 후 일치 거래 중 상위 K개 선택 | `O(N + R log(K+1))` |
| 요약 | 전체 합산, 카테고리 정렬, 예산 조회 | `O(N + C log(C+1) + B)` |
| 거래 추가 | 최대 ID 조회, 중복 ID 검사, 파일 추가 | `O(N)` |
| 거래 수정·삭제 | 존재 확인 후 파일 전체 재작성 | `O(N)` |
| CSV 가져오기 | 최대 ID 1회 조회, 기존 거래 복사, 새 행 순차 기록 | `O(N + M)` |
| CSV 내보내기 | 전체 순회·필터링·CSV 기록 | `O(N)` |

### 이미 적용한 개선

- CSV 가져오기에서 최대 ID를 한 번만 읽고, 정상 행마다 메모리의 번호를 증가시킵니다.
- 각 행마다 개별 저장하지 않고 임시 파일에 기록한 뒤 한 번에 교체합니다.
- 목록·검색은 출력 제한에 비례하는 거래만 보관합니다. 요약은 거래 목록 대신 카테고리별 합계를 보관합니다.
- CSV 가져오기는 전체 CSV를 메모리에 쌓지 않습니다. 등록 카테고리 집합과 현재 처리 중인 행 등을 보관합니다.

### 남아 있는 병목과 개선 방향

기존 거래 100,000건과 CSV 1,000행을 처리하면, ID 조회에서 기존 거래를 한 번 읽고 임시 파일 작성에서 다시 복사한 뒤 CSV 행을 처리합니다. 따라서 거래마다 100,000건을 다시 읽는 구조는 아닙니다. 다만 공통 카테고리 복구도 별도로 거래 전체를 순회하고, 원자적 저장을 위해 기존 데이터 크기에 비례하는 임시 디스크 공간이 필요합니다.

- **카테고리 자동 복구:** 매 명령마다 기본적으로 `O(N)` 순회가 추가됩니다. 복구할 이름이 있으면 카테고리 중복 확인을 위한 파일 읽기도 발생합니다. 필요할 때만 실행하도록 분리하는 것이 개선 후보입니다.
- **수정·삭제:** 거래 한 건을 바꾸더라도 전체 파일을 재작성합니다. 현재 과제에서는 안전한 파일 교체를 유지하고, 규모가 커질 때 파일 분할 등을 검토할 수 있습니다.
- **검색·요약:** 특정 월만 요청해도 전체 거래를 읽습니다. 월별 파일 분할이나 별도 인덱스·합계 캐시는 후보지만, 수정·삭제와 일관성을 유지하는 설계가 추가로 필요합니다.
- **동시 수정:** 파일 잠금이나 다른 저장 체계가 필요합니다. 데이터베이스 전환은 JSONL/CSV 저장 조건을 벗어나는 별도 확장 방향이며 현재 구현에는 포함하지 않습니다.

## 7. 테스트

프로젝트 최상위 폴더에서 실행합니다.

```bash
python3 -B -m unittest discover -s tests -v
```

테스트는 임시 데이터 폴더를 사용합니다. CLI 테스트도 `--data-dir`로 임시 폴더를 지정하므로 실제 `data/`를 대상으로 실행하지 않습니다.

| 파일 | 주요 검증 |
|---|---|
| `test_repository.py` | 저장·재조회, 수정·삭제 시 다른 거래 보존, 중복·없는 ID, ID 생성, 일괄 저장 롤백 |
| `test_stores.py` | 카테고리 중복·삭제·빈 이름, 예산 유지·변경·미설정 |
| `test_validators.py` | 날짜·윤년·월·기간·타입·금액 검증 |
| `test_csv_io.py` | CSV 교환, 기간 필터, 저장 파일 덮어쓰기 차단, 내보내기 실패 시 기존 파일 보존 |
| `test_cli.py` | 명령별 도움말, 별도 프로세스 간 CRUD, 종료 코드, 예산 조회, 잘못된 CSV 안내·거래 보존 |

현재 테스트 메서드는 40개이며, 일부는 여러 입력을 `subTest`로 확인합니다. 통과 결과는 이 테스트 범위에 대한 확인이며 모든 파일 손상이나 동시 실행 상황까지 보장하지는 않습니다.
